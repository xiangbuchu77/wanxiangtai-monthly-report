# 万相台周期报表 Skill

## 运行方式

- 交付版是可独立运行的 Skill，业务服务位于 `assets/service/`。
- 开发仓库中也兼容调用同级共享 `runtime/`，两种布局使用同一入口。
- 不需要 API Key；截图识别与文案增强使用 QClaw/OpenClaw 当前会话的内置模型。

## 触发规则

- 用户上传 `csv`、`xls`、`xlsx`、`zip` 或数据截图（`png`、`jpg`、`jpeg`、`webp`）后，只要明确说“生成月报”“生成半月报”“生成周报”“制作报表”“导出 Excel”等，就立即生成报表。
- 用户一句话同时要求“月报、半月报、周报”时，一次调用脚本生成多个周期文件。
- 不要先等待用户二次确认，不要反复询问是否还有文件。
- 只有用户只是上传文件、没有表达生成意图时，才简短询问是否现在生成以及生成哪个周期。
- 不得因为用户只提到“Excel”“月报逻辑”或提出分析问题就擅自生成；必须存在“生成、制作、导出、输出”等明确动作。

## 执行方式

唯一执行入口：

```bash
python scripts/call_local_agent.py --text "生成周报、半月报、月报" --file file1.xlsx --file file2.csv
```

不要手动启动服务，不要手动检查 Python，不要拆成多步执行。`call_local_agent.py` 会优先使用 Skill 内置服务，并自动启动一次；开发环境没有内置服务时才使用共享 `runtime/`。

脚本成功后会输出 `MEDIA:<最终xlsx绝对路径>`。必须把每条 `MEDIA:` 对应的 Excel 作为 QClaw 文件附件直接返回用户；不要只复述本地路径，不要再次运行生成脚本。

## 生成原则

- 月报：近30天 vs 前30天。
- 半月报：近15天 vs 前15天。
- 周报：近7天 vs 前7天。
- 最新一天以用户上传文件中能识别到的最大日期为准。
- 月报、半月报、周报分别使用 `templates/` 下的独立模板。
- `zip` 由服务统一解包一次；不要让模型先手动解压再重复传入。若返回“损坏、加密或没有可处理文件”，原样提示压缩包问题，不要误报为缺少业务指标。
- 同一批截图通过 QClaw/OpenClaw 内置视觉模型一次识别，并按店铺和日期合并互补指标；重复截图数值不得相加，未能可靠识别的指标保持缺失，不得编造。
- 只读取上传文件中的数值并填入模板，不改模板结构。
- 第二部分主要商品数据只填 Top4，字段为 `商品名称`、`广告花费`、`广告ROI`、`操作建议`。
- 4.2 预算分配只展示数据中真实出现过的推广渠道，未出现的渠道不要写入。
- 文字说明、预算分配、操作规划、总结建议使用 QClaw/OpenClaw 内置模型增强。
- 最终只返回用户明确要求的 `月报.xlsx`、`半月报.xlsx` 或 `周报.xlsx`。不得创建、返回或称呼为“推广月报”“标准经营总表”“数据半成品”“数据缺失报告”“AI分析”或其他额外文件。

## Windows 环境

如果 QClaw 提示需要 `QCLAW_PYTHON_BINARY`，让用户在 cmd 中永久设置一次：

```bat
setx QCLAW_PYTHON_BINARY "C:\Program Files\Python312\python.exe"
```

设置后重启 QClaw。
